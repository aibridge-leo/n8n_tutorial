n8n이란?

n8n은 데이터를 옮기는 도구입니다

데이터를 수집하고 · 가공하고 · 활용하고 · 전송하는 것

AI Agent, MCP, RAG 같은 말은 전부 이 네 가지를 더 잘하기 위한 장치입니다

기본을 놓치면 생기는 일

새 기능 이름만 쫓아다니면 깊이가 안 생깁니다. 에이전트가 답을 못 할 때 "프롬프트를 고쳐야 하나"부터 떠올리지만, 실제 원인은 애초에 데이터가 안 들어왔거나, 형태가 안 맞았거나인 경우가 대부분입니다.

그래서 오늘의 순서

오전에 데이터를 다루는 감각을 먼저 잡습니다. 어떤 모양으로 들어와서 어떻게 바뀌어 나가는지. 오후 AI 실습에서 문제가 생겼을 때, 이 감각이 있으면 어디를 봐야 할지 알게 됩니다.

공식 정의: 노코드/로우코드로 API·LLM·서비스·데이터 흐름을 연결해 워크플로우를 자동화하는 도구. 말은 어렵지만, 결국 "이거 가져와서, 이렇게 바꿔서, 저기로 보내"입니다.

n8n이 선택받는 세 가지 이유

01
용이성

노코드/로우코드. 개발 지식 없이도 드래그 앤 드롭으로 만듭니다. 오늘 이 강의가 성립하는 이유입니다.

02
확장성

텔레그램·노션·슬랙·구글… 일상에서 쓰는 서비스 대부분이 노드로 준비되어 있고 계속 늘어납니다.

03
유연성

생성형 AI가 개입해 문장 같은 비정형 데이터를 다루고, 스스로 판단해 도구를 골라 씁니다.

다른 도구와 비교하면

Zapier·Make도 비슷한 일을 합니다. n8n의 차별점은 ① 소스가 공개되어 직접 서버에 설치할 수 있고, ② 과금이 '실행 횟수' 기준이라는 점입니다. 단계가 10개든 30개든 1회 실행은 1회로 계산됩니다. 단계마다 과금하는 도구와 비용 차이가 크게 벌어지는 지점입니다.

솔직한 단점

화면이 기본 영어입니다. 다국어 기능이 있고 한국어 번역도 진행되어 왔지만, 사용하는 버전·환경에 따라 적용 여부가 다릅니다. 오늘은 영문 화면 기준으로 진행합니다.

노드 이름은 영문으로 짧게 짓기를 권합니다. 표현식에서 노드 이름을 참조하게 되는데, 영문이 훨씬 다루기 쉽습니다.

Workflow — 자동화 그 자체

노드들이 연결된 전체 그림. "안 읽은 메일을 요약해서 나에게 보낸다"는 계획 하나가 워크플로우 하나입니다.

Node — 일하는 단위 하나

아이콘 하나하나. 데이터를 받아서(INPUT) → 뭔가 하고 → 내보냅니다(OUTPUT). 그 출력은 다음 노드의 입력이 됩니다.

Trigger — 시작 버튼

워크플로우가 1회 실행된 이력. 언제 돌았고, 어떤 데이터가 흘렀고, 어디서 멈췄는지가 전부 남습니다.

Pin — 실습 속도를 두 배로

데이터 고정 (Pin)

OUTPUT 패널 우측 상단의 핀 아이콘을 누르면 지금 나온 결과가 고정됩니다. 이후 워크플로우를 실행하면 이 노드는 실제로 돌지 않고 고정된 값을 그대로 내보냅니다.

왜 필요한가

테스트할 때마다 메일함 상태가 바뀌면, 문제가 내 설정 때문인지 데이터가 바뀌어서인지 구분이 안 됩니다. 고정해두면 변수가 하나 사라집니다.

데이터 수정 (Edit Output)

핀 옆 연필 아이콘으로 출력값을 직접 고칠 수 있습니다. "이런 값이 들어오면 어떻게 되지?"를 실제 데이터 없이 시험할 때 유용합니다.

반드시 기억할 것

최종 테스트 전에는 핀을 풀어야 합니다. 노드 우클릭 → Unpin. 고정된 채로 두면 실제 데이터가 아닌 옛날 값으로 계속 돌아갑니다.

프롬프트는 두 종류입니다

System Prompt — 배경 설정

역할·성격·말투·출력 형태·금지사항을 정합니다. 사용자에게는 보이지 않지만 모든 답변에 항상 영향을 줍니다.

당신은 이름이 Nova인 개인 비서입니다. 답변은 3문장 이내로 간결하게 합니다. 확실하지 않으면 모른다고 말합니다.
User Prompt — 실제 질문

사용자가 그때그때 보내는 내용. Expression으로 연결해서 실행할 때마다 달라지게 만듭니다.

{{ $json.chatInput }} // 사용자가 입력한 메시지가 // 그대로 들어옵니다
왜 시스템 프롬프트가 중요한가

같은 질문이어도 시스템 프롬프트에 따라 답이 완전히 달라집니다. "3문장 이내"를 넣지 않으면 열 문장을 씁니다. "모르면 모른다고 하라"를 넣지 않으면 그럴듯하게 지어냅니다. 자유분방한 AI를 업무에 맞게 통제하는 장치라고 생각하세요.

문제 3
지어냅니다

LLM은 다음에 올 법한 말을 확률로 고르는 구조입니다. 사실이 아니라 그럴듯한 문장을 만드는 것이 기본 동작이라, 근거가 없으면 지어냅니다.

그래서 RAG

문서를 미리 잘게 잘라 보관해두고, 질문이 들어오면 관련된 조각 몇 개만 찾아서 AI에게 함께 건네는 방식입니다.
200쪽을 다 읽히는 대신, 필요한 3문단만 펼쳐서 보여주는 것이라고 생각하면 됩니다.

RAG = Retrieval(검색) Augmented(보강) Generation(생성). 이름 그대로 검색해서 보강한 뒤 답을 생성한다는 뜻입니다.

잘 맞는 일
  • 반복되는데 판단이 조금 필요한 일 — 문의 분류, 우선순위 매기기
  • 정보를 모아 정리하는 일 — 리서치 요약, 리포트 초안
  • 여러 곳을 오가며 확인하는 일 — 메일·시트·캘린더 대조
  • 물어보면 답해주면 되는 일 — 사내 규정, 매뉴얼 안내
맞지 않는 일
  • 정확히 같은 결과가 나와야 하는 일 — 급여 계산, 세금 신고
  • 틀리면 되돌릴 수 없는 일 — 대금 지급, 계약 체결
  • 민감정보를 다루는 일 — 외부 API로 나가는 순간 검토 필요
  • 한 달에 두세 번 하는 일 — 만드는 시간이 더 듭니다
