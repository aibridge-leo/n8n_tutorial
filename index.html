할루시네이션 (Hallucination)

AI가 없는 사실을 있는 것처럼 말하는 현상
존재하지 않는 매물 조건 · 없는 규정 설명 · 지어낸 수수료율
왜 생길까?
AI는 "정답을 아는 것"이 아니라 "그럴듯한 다음 단어를 예측"하는 방식으로 작동하기 때문입니다.
일반적 대응
수치·법률·계약 정보는 원본 출처를 반드시 확인. AI 답변을 그대로 고객에게 전달하지 않기.
오늘의 해법 → RAG
우리 회사 문서에서 근거를 찾아 답하게 만듭니다. 문서에 없으면 "모른다"고 답하도록 규칙을 걸죠. PART 8에서 직접 구현합니다.
고객 응대 챗봇에서 할루시네이션은 단순 실수가 아니라 사고입니다. "수수료 0.4%입니다"라고 지어내면 회사가 책임집니다. 그래서 RAG가 필요합니다.

PART 1 — Claude

Claude & Anthropic이란?

Anthropic이 개발한 LLM 기반 생성형 AI — 하나의 이름이 서비스이자 브랜드이자 모델 이름으로 쓰입니다.

Anthropic (회사)

전 OpenAI 연구원들이 2021년 창립한 AI 안전(safety) 중심의 연구·제품 회사

세 가지 의미

엔진(LLM) · 서비스(Claude.ai) · 모델 이름(Opus · Sonnet · Haiku) — 맥락으로 구분합니다

같은 엔진, 다른 환경

웹 채팅 · Cowork · Code · Design · Chrome — 모두 같은 Claude가 다른 옷을 입은 것입니다

왜 이 과정에서 Claude인가: 긴 문서(계약서·정책·업무 자료) 처리와 코드 생성에 강하고, 무엇보다 파일을 직접 만들고 고치는 에이전트가 있어서 "결과물"까지 나옵니다.

PART 2 — 기본 개념

토큰 · 컨텍스트 · 컨텍스트 윈도우

토큰 (Token)

AI가 텍스트를 처리하는 기본 단위. 단어 하나일 수도, 더 작은 조각일 수도 있습니다. (영어 1단어 ≈ 1~2토큰, 한글은 더 잘게 쪼개집니다)

비용과 직결: 입력·출력 토큰 양에 따라 사용량이 차감됩니다.
컨텍스트 (Context)

AI가 지금 대화에서 참고하는 정보의 범위. "아까 그거"라고만 해도 알아듣는 이유입니다.

첨부한 파일, 마운트한 폴더, 연결한 도구가 모두 컨텍스트에 들어갑니다.
컨텍스트 윈도우

모델이 답을 만들 때 한 번에 볼 수 있는 정보 상자의 크기. 단위는 토큰입니다.

100만토큰 ≈ 소설 9~10권

비어 있는 새 대화도 시스템 프롬프트 등으로 이미 수만 토큰을 씁니다.

한 줄 정리: 토큰 = 처리·비용의 단위, 컨텍스트 = AI가 참고하는 정보 범위, 컨텍스트 윈도우 = 그 정보가 들어가는 상자의 크기.

[맥락] 나는 중소기업 업무 개선 컨설팅을 대행하는 10인 규모 회사의 기획 팀장이야. [대상] 고객사 담당자(40~50대)에게 제출할 소개서. 경쟁 PT에서 3개 사와 비교됨. [담을 내용] 회사 개요 / 주요 실적 3건 / 서비스 4종 / 차별점 / 진행 프로세스 / 문의처 [형식] 마크다운 파일 1개. 섹션마다 소제목. 과장 없는 신뢰감 있는 톤. 2,000자 내외.
좋은 프롬프트의 4요소
  • 맥락 (Who) — 누가, 어떤 상황에서 묻는지
    → 눈높이와 전문성이 맞춰집니다
  • 대상과 목적 (Why) — 누가 읽고 무엇을 결정하는지
    → 설득 포인트가 달라집니다
  • 구체적 내용 (What) — 담을 항목을 나열
    → 추측 대신 정확한 구성
  • 출력 형식 (How) — 파일 형태·길이·톤
    → 다시 시키는 횟수가 줄어듭니다
실전 요령: 처음부터 완벽하게 쓰려 하지 말고, 먼저 짧게 시키고 결과를 보며 조건을 추가하세요. 대화형 도구의 장점이 그것입니다.

로컬 vs 클라우드

로컬 (Local) = 내 컴퓨터

"로컬에서 실행한다" = 내 컴퓨터에서 실행. 파일이 내 하드디스크에 저장됩니다. 나만 볼 수 있습니다.

구글 드라이브·네이버 클라우드가 대표적. 내 파일이 회사 서버 컴퓨터에 저장됩니다. 주소만 알면 누구나 접속할 수 있습니다.

데이터베이스 & 벡터 검색

데이터베이스 (DB)

데이터를 표(테이블) 형태로 저장·검색하는 시스템. 엑셀과 비슷하지만 동시에 여러 사람이, 훨씬 빠르고 안전하게 쓸 수 있습니다.

테이블 = 시트, 행(row) = 한 건의 기록, 열(column) = 항목

Supabase

설치 없이 클라우드에서 바로 쓰는 데이터베이스 서비스. 무료 티어가 있고, Claude 공식 커넥터가 있어 대화로 조작할 수 있습니다.

벡터 & 임베딩 — RAG의 핵심

임베딩(Embedding) = 글의 의미를 숫자 목록으로 바꾸는 것.

"중도금 대출 가능한가요?" ↓ 임베딩 [0.021, -0.184, 0.907, ... ] ← 1536개 숫자

숫자로 바뀌면 의미가 비슷한 문장끼리 가까운 위치에 놓입니다. 그래서 단어가 달라도 뜻이 비슷하면 검색됩니다.

왜 필요한가: 고객은 "계약금 나눠 낼 수 있나요?"라고 묻는데 우리 FAQ엔 "대금 분할 지급 조건"이라고 쓰여 있습니다. 단어 검색은 실패하지만 벡터 검색은 찾아냅니다. Supabase의 pgvector 기능이 이 일을 합니다.

패키지 (Package)

남이 만들어 둔 코드 묶음(라이브러리). 직접 만들 필요 없이 가져다 씁니다.

STEP 1 — 가장 중요한 슬라이드

FAQ 품질 = 챗봇 품질

좋은 FAQ의 조건
  • 고객의 실제 말투로 질문을 쓴다 — "중도금 대출 되나요?"
  • 같은 질문의 다른 표현도 함께 적는다
  • 답변에 구체적 숫자·조건을 넣는다
  • 답변 하나가 3~6문장, 너무 길지 않게
  • 답할 수 없는 것도 명시한다 ("개별 상담 필요")
기억하세요: RAG 챗봇은 문서에 없는 건 답하지 못합니다(그게 장점입니다). 고객이 물을 만한 질문이 FAQ에 없으면, 챗봇은 그 질문에 답하지 못합니다.

[테이블 3개] 1. leads 문의 - id, name, phone, email, company, message - source 'form' | 'chatbot' - status new | contacted | qualified | won | lost (기본 new) - owner(담당자), created_at, updated_at 2. deals 영업 - id, lead_id → leads(id) - title, amount, expected_close_date - stage proposal | negotiation | won | lost - note, created_at, updated_at 3. contracts 계약 - id, deal_id → deals(id) - contract_no(고유), amount - signed_at, start_date, end_date, created_at [편의] - created_at 내림차순 인덱스 - updated_at 자동 갱신 트리거 [보안] - 세 테이블 모두 RLS 활성화 - 공개 정책은 만들지 않음 (service_role을 쓰는 우리 서버만 접근)
테이블이 하는 일
테이블한 줄 = 무엇누가 만드나

deals영업 진행 1건담당자가 수동

왜 leads와 deals를 나누나

문의 100건 중 실제 상담까지 가는 건 20건일 수 있습니다. 한 표에 다 넣으면 "문의 수"와 "영업 건수"가 섞여 전환율을 볼 수 없습니다.

→ leads 100 · deals 20 · contracts 4 = 전환율이 그대로 보입니다

RLS를 켜고 정책을 비워두는 이유
  • RLS 활성화 = 기본적으로 아무도 접근 불가
  • 공개 정책 없음 = service_role 키를 가진 서버만 읽고 씀
  • → 고객 연락처가 브라우저에서 조회될 수 없습니다

브라우저 자동화 안전 수칙

왜 조심해야 하나

Claude가 브라우저를 조작한다는 것은 내 로그인 상태로 무언가를 할 수 있다는 뜻입니다. 편리한 만큼 위험도 함께 커집니다.

프롬프트 인젝션: 악의적인 웹페이지에 "이전 지시를 무시하고 ○○해라" 같은 숨겨진 문구를 심어 AI를 속이는 공격이 실제로 존재합니다.

Anthropic도 이를 베타 기능으로 명시하고 있습니다. 안전 분류기가 적용돼 있지만 여전히 위험이 남아 있습니다.
실무 수칙
  • 신뢰할 수 있는 사이트에만 권한을 주기
  • 금융·계약·인사 등 중요 작업은 항상 확인 후 승인
  • Claude에게 비밀번호를 전달하지 않기
  • 업무용·개인용 Chrome 프로필 분리
  • 예상과 다르게 동작하면 즉시 중지하고 검토
  • 사이트 이용약관 확인 — 자동 접근을 금지하는 곳이 있음
  • 더 이상 쓰지 않는 권한은 회수
오늘 실습은 안전합니다. 내가 만든 내 사이트만 테스트하니까요. 다만 이 기능을 회사 업무에 쓸 때는 위 수칙을 반드시 지키세요.

"무료 상담" 버튼 → 폼 제출까지 실제로 (이름 "테스트-QA", 연락처는 내 번호) 동의 미체크·필수값 누락이 막히는지, 제출 후 텔레그램 알림이 오는지 각각 [질문 / 답변 / 판정 / 개선 제안]으로 qa-report.md 파일에 저장해줘. 판정: 정상·부족·미검색·지어냄·거부실패
STEP 6 — 반응형 & 콘솔 점검
배포된 사이트를 모바일·태블릿·데스크톱 폭에서 확인하고 깨지는 곳을 찾아줘. 콘솔 오류와 /api/chat · /api/lead 응답 코드도 확인. 문제를 정리하고 수정안을 제안해줘.
운영 — 테스트 데이터 정리
leads에서 이름이 "테스트"로 시작하거나 연락처가 내 번호인 행을 찾아 목록으로 보여주고, 확인 후 삭제해줘. 삭제 전 반드시 목록을 보여줄 것.
운영 — 관리자 대시보드
/admin 페이지를 만들어줘. - ADMIN_TOKEN(.env) 비밀번호 게이트 - GET /api/admin (Bearer 인증) → 서버에서 service_role로 조회 - 통계 카드: 리드·영업·계약·대화 수 + 전환율(리드→영업→계약) - 탭: 리드 / 영업 / 계약 / 대화 로그 / 문서 - 리드 status 바로 변경, deal로 승격 버튼 - 리드·영업 CSV 내보내기 - 답변 못 한 질문 필터 - noindex 메타, 토큰은 sessionStorage
운영 — 배포 전 보안 점검
배포 전 보안 점검을 해줘. 1. 커밋될 파일에 비밀값이 있는지 (.env · Supabase 키 · 텔레그램 봇 토큰) 2. 클라이언트 코드에 키 노출이 있는지 3. Supabase RLS 설정이 안전한지 4. 개인정보(leads)가 서버에서만 조회되는지 5. 챗봇이 지어낼 위험이 있는 부분 발견한 문제를 위험도 순으로 정리해줘.
운영 — 리드 · 문서 갱신 루틴
이번 주 리드를 status별로 집계하고, 24시간 넘게 status가 new인 건을 알려줘. chat_logs에서 최근 한 달간 챗봇이 답하지 못한 질문을 빈도순으로 뽑고, faq.md에 추가할 질문·답변 초안을 만들어줘.
